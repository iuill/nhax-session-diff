# 要件と調査計画

## 利用背景

- 利用者は本人のみ。複数人向けのアカウント管理は不要。
- フィッティングソフトウェアからエクスポートしたNHAXを利用する。
- セッション間で何を変更したかを確認したい。
- 同じ本人を別名のユーザーとして保存する場合がある。
- NHAXエクスポートからセッション履歴を取得できるか調べる。

## 比較の要件

- 比較元・比較先は独立して選択し、同一ユーザーであることを条件にしない。
- 元のファイル、元のユーザー識別子、元のセッション識別子を追跡可能にする。
- 再エクスポートで同一データが含まれる場合も出典を残す。
- 名前や日時だけで同一人物・同一セッションと判定しない。
- 設定値の変更・追加・削除を区別する。
- 左右、プログラム、周波数、入力レベル、単位は実データで存在が確認できた場合に保持する。
- 不透明なメーカー固有データはハッシュやサイズを比較できるが、設定の意味は推測しない。
- 補聴器への書き込みやフィッティングの推奨は対象外。

## 実装前に確認すること

1. フィッティングソフトウェアのバージョンとエクスポート方法を記録する。
2. セッションを2つ以上含むNHAXでコンテナ形式を確認する。
3. ユーザー、セッション、アクションの階層と識別子・日時を確認する。
4. フィッティングデータがXML、圧縮データ、メーカー独自バイナリなどのどれかを確認する。
5. 可能なら、既知の設定を1項目だけ変えた前後の保存データを比較する。
6. 解読した項目がフィッティングソフトウェア画面の値と一致するか確認する。
7. セッション抽出と正規化を実装し、実データを含まない合成データで検証する。
8. 読める範囲が判明してから比較UIを決める。

## 調査済みの公開情報

2026-10-10確認。

- [HIMSA: Noahのアクセス権の説明](https://www.himsa.com/de/support-2/noah-4-knowledgebase-german/trainingscenter/benutzerzugangslevel-und-starke-passworte/)
  は、Noah形式のエクスポートが患者の人口統計情報と全アクションデータを含むと説明している。
- [HIMSA: Encrypting Noah Exports](https://www.himsa.com/news/encrypting-noah-exports/)
  は、パスワード付きエクスポートを `.enhax`、標準エクスポートを `.nhax` としている。
- [HIMSA: Smartcare認証資料](https://www.himsa.com/wp-content/uploads/2020/05/Smartcare2.4Noah4MobileCertificationMay7_2019.pdf)
  には、NHAXを空のNoahデータベースへインポートし、分析用XMLへエクスポートする手順がある。
  Noahが利用可能な場合の代替調査経路であり、フィッティングソフトウェア単体で同じ機能があるとは未確認。

公開情報だけでは、フィッティングソフトウェアエクスポートに全セッションや全設定が含まれると断定できない。

## 実サンプルで確認できた形式

2026-10-10、提供された1ファイルをローカル解析。個人情報や抽出された値はこの文書に含めない。

- 40バイトのヘッダー。先頭にリトルエンディアン32ビット値のヘッダー長40、バージョン1。
  続く8バイトは `88 99 00 dd cc bb aa 00`。残りのヘッダーの意味は未確認。
- レコードは32ビット長（ヘッダー込み）と32ビット種別を持つ。
- 種別 `0x80000005` は展開後サイズの32ビット値とzlib圧縮されたPatient XML。
- 末尾の種別3はUsers XML、種別2はPatientsインデックスXML。
- Patient → Sessions → Session → Action の階層。Sessionの日付だけでなく、
  Actionには時刻を含むCreateDateとActionGroupがある。両者を混同しない。
- PublicData / PrivateData はBase64。PrivateDataはcompression要素、
  `zip_size` バイトのbzip2データ、`<compressionend/>` で構成される。
- bzip2展開後はUTF-16LE XML。ClientProfile、SelectionData、FittingData、InstrumentLoggingDataを確認。
- FittingDataのPath付きレジスターとEndUserSettingsのKey付き辞書は項目別の比較が可能。

この1ファイルで観察した形式だけに対応するパーサーを実装した。
他のフィッティングソフトウェアバージョンやエクスポート、暗号化されたENHAXへの対応は未確認。
XML名の意味、数値の単位、situationの番号とUIのプログラムとの対応は追加検証が必要。
